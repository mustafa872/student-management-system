## Error 001 — `authorize()` غير معرّفة

- **الموضوع:** Laravel Authorization
- **الحالة:** سبق أن عولجت المشكلة؛ يُعاد التحقق منها عند الحاجة.
- **المشكلة:** ظهور خطأ يفيد بأن `authorize()` غير معرّفة أو غير متاحة في Controller.
- **السبب الذي عولج سابقاً:** كان Controller الأساسي يحتاج إلى إتاحة Trait `AuthorizesRequests` بحسب بنية المشروع في ذلك الوقت.
- **الإصلاح السابق:** إضافة الاستيراد واستخدام الـ Trait المناسب في Controller الأساسي:

```php
use Illuminate\Foundation\Auth\Access\AuthorizesRequests;
```

ثم داخل تعريف Controller الأساسي:

```php
use AuthorizesRequests;
```

- **التحقق:** فحص الصياغة وتشغيل العملية والتأكد من أن الصلاحيات تُطبّق كما هو متوقع.
- **تنبيه:** قبل تكرار هذا الإصلاح، تحقق من إصدار Laravel ومن محتوى Controller الفعلي؛ لا تضف Trait مكرراً أو غير مطلوب.

## Error 002 — `403 This action is unauthorized`

- **الموضوع:** Policy / Authorization
- **المعنى:** رفض Laravel الطلب بسبب عدم اجتياز فحص الصلاحية.
- **السبب المحتمل:** المستخدم لا يملك صلاحية تنفيذ العملية وفق Policy، أو أن Policy لا تسمح بالحالة الحالية.
- **طريقة التشخيص:**
    1. تحديد المستخدم المسجّل دخوله.
    2. التحقق من سجل الطالب ومالكه.
    3. مراجعة شرط Policy.
    4. التأكد من ربط Policy بالموديل بالطريقة الصحيحة.
    5. التحقق من أن الرفض متوقع وليس خطأً في منطق الصلاحيات.
- **التحقق من الإصلاح:** المستخدم المصرح له يستطيع تنفيذ العملية، والمستخدم غير المصرح له يُرفض طلبه.
- **تنبيه أمني:** لا تعالج المشكلة بإزالة `authorize()` أو بالسماح للجميع دون سبب واضح.

## Error 003 — أخطاء الصياغة في PHP

- **الموضوع:** PHP Syntax
- **المشكلة السابقة:** ظهور Parse Error قرب تعريف دالة `edit()`.
- **الإجراء السابق:** إزالة أحرف غير متوقعة قرب تعريف الدالة ثم فحص الملف.
- **أداة التحقق:**

```bash
php -l app/Http/Controllers/StudentController.php
```

- **النتيجة المتوقعة عند سلامة الصياغة:** `No syntax errors detected`.
- **الدرس:** نجاح فحص الصياغة لا يعني أن منطق البرنامج أو الصلاحيات صحيحان؛ يجب اختبار السلوك أيضاً.

## Error 004 — يجب التحقق قبل التسجيل

- **الموضوع:** `user_id` و Record Ownership
- **المشكلة المحتملة:** الاعتماد على قيمة `user_id` القادمة من النموذج لإنشاء سجل طالب أو تغيير مالكه.
- **الخطر:** قد يحاول المستخدم ربط السجل بحساب شخص آخر إذا لم تتم الحماية.
- **المبدأ الآمن:** قيمة المالك يجب أن تُحدّد من هوية المستخدم الموثّق بعد التحقق من تسجيل الدخول، لا من قيمة يرسلها العميل.
- **التطبيق النهائي:** يُسجّل بعد فحص كود الإنشاء والتحديث الحالي واختبارهما.
