# المختبر العملي — تمارين تدريجية مرتبطة بالمرجع

> هذه مختبرات متدرجة لتطبيق ما في `MASTER-REFERENCE.md`. بعضها جديد ولم ننجزه بعد. كل مختبر يحدّد المتطلبات، خطوات التجربة، والنتيجة المطلوبة، دون تسليم حل كامل قبل محاولة المتعلم.

## LAB-01: من HTTP إلى Route
**المتطلبات:** الفصول 01،06،07،08. **الهدف:** تفسير رحلة الطلب.
1. نفّذ `php artisan route:list --path=students`.
2. حدد GET index وGET edit وPATCH update وDELETE destroy.
3. ارسم لكل Route: URL -> Middleware -> Controller Method -> Response.
4. **تحقق:** لماذا GET edit لا تحفظ شيئاً؟ ماذا تعني 404 و403؟
5. **المخرج:** جدول بأربعة مسارات مع توضيح المصدر.

## LAB-02: Form + Validation
**المتطلبات:** 11،12،13. **الهدف:** فهم صحة المدخلات.
1. على نسخة تدريبية، صمّم Form فيه `name`, `age`, `stage`, `email`.
2. استخدم `@csrf` و`old()` و`@error()`.
3. اختبر: اسم قصير، عمر خارج المدى، بريد مكرر، مرحلة غير مقبولة.
4. **تحقق:** سجل ماذا يظهر للمستخدم وماذا يمنع الحفظ.
5. **تحدٍ:** لماذا يجب السماح بإبقاء بريد الطالب الحالي عند التحديث؟

## LAB-03: Migration + Eloquent
**المتطلبات:** 05،14،16. **الهدف:** فرق Schema وModel.
1. على قاعدة اختبار منفصلة، اكتب Migration لجدول تدريبي `clubs`، وModel مناسباً.
2. حدد Primary Key وفهرساً مناسباً.
3. نفّذ إنشاء سجل واحد، ثم قراءة، تعديل، حذف داخل Test.
4. **تحقق:** هل الـ Model يخلق الجدول وحده؟ هل Validation تنشئ Index تلقائياً؟
5. **تحذير:** لا تستعمل `migrate:fresh` على قاعدة مشروعك اليومية.

## LAB-04: العلاقات وN+1
**المتطلبات:** 17،18. **الهدف:** رسم Relations وتتبع Queries.
1. ارسم `users -> students`, `students -> books/card`, `students <-> courses`.
2. حدد Foreign Keys وجدول Pivot.
3. اكتب من الذاكرة الفرق بين `with`, `load`, `sync`.
4. **تحقق:** أي تغيير يمكن أن يجعل `sync([])` يفصل جميع الدورات؟
5. **المخرج:** مقارنة Query count قبل/بعد Eager Loading في بيئة تطوير.

## LAB-05: الملفات والصور
**المتطلبات:** 12،19،21. **الهدف:** اختبار مسار رفع صورة آمن.
1. احمِ Route التعديل بسياسة `update`.
2. ارفع صورة صغيرة صالحة إلى Public Disk.
3. اختبر فشل ملف غير صالح.
4. استبدل صورة مع حفظ مسار القديمة لحين التأكد من نجاح الحفظ.
5. **تحقق:** إن فشل DB بعد رفع ملف، كيف تتجنب ملفاً يتيماً؟

## LAB-06: Policy::before() (الدرس الجاري)
**المتطلبات:** 20،21. **الهدف:** تتبع قرار الصلاحيات.
1. لا تكتب كوداً أولاً؛ املأ جدول Owner/Non-owner/Admin/Blocked/Admin+Blocked.
2. قارن `before()` التي تفحص blocked أولاً بالتي تفحص admin أولاً.
3. اشرح الفرق بين true وfalse وnull دون النظر للمرجع.
4. اشرح لماذا يلزم وجود Ability method مطابقة في الـ Policy.
5. اختبر `Gate::forUser()->allows()` على بيانات اختبار لا تحذفها.
6. **تحدٍ:** احمِ `show()` و`edit()` و`update()` في Server، لا Blade فقط.

## LAB-07: Feature Test على 403
**المتطلبات:** 21،35،36. **الهدف:** حماية قابلة للإعادة.
1. جهّز قاعدة اختبار منفصلة وFactory لUser وStudent.
2. Arrange: مستخدمان وطالب أحدهما مالكه.
3. Act: سجل الدخول بالآخر واطلب Route edit.
4. Assert: يجب أن تكون 403 والطالب غير معدّل.
5. **تحدٍ:** أضف حالة Guest وحالة Owner، وقارن 302 و200 و403.

## LAB-08: Student JSON API
**المتطلبات:** 21،33،34،35. **الهدف:** API محمية.
1. صمّم Resource يحتوي فقط `id/name/stage`.
2. اكتب مسارات index/show/update بصورة تخطيطية.
3. اختبر 200 للمالك، 403 لغير المالك، 404 لرقم غير موجود، 422 لمدخل غير صالح.
4. **تحقق:** Authentication لا يغني عن Policy.

## LAB-09: Cache/Queue
**المتطلبات:** 27،29. **الهدف:** فرز المتزامن من المؤجل.
1. قرر أي جزء يستحق Cache (عدد الطلاب مثلاً).
2. صف متى تبطل نتيجة Cache.
3. عرّف مهمة تصدير تقرير Job وارسم مسار Worker.
4. **تحقق:** ماذا يحدث عند Connection = sync؟ وماذا عند فشل Worker؟

## LAB-10: Project Audit وتجهيز نشر تجريبي
**المتطلبات:** 22،35،39،40. **الهدف:** تقييم جودة المشروع.
1. اكتب Matrix بالمسارات والأدوار والصلاحيات.
2. اكتب جدول الاختبارات الناقصة والأخطاء المتبقية.
3. افصل Secrets عن Git، وراجع `APP_DEBUG` وبيئة DB.
4. تحقق من `npm run build` ووجود backup واستراتيجية rollback.
5. **المخرج:** تقرير 1-2 صفحة: الميزات، المخاطر، الاختبارات الناجحة، ما لم يُختبر.
