# 🧠 بنك الأسئلة — من PHP إلى Laravel Policies

**الإصدار:** 1.0.0 — 2026-10-31.  
**تعليمات الاستخدام:** لا تفتح الإجابات إلا بعد المحاولة. في كل درس نختار عادةً **6 أسئلة متنوعة**: مفهوم، تتبع كود، تصحيح خطأ، سيناريو، أمان، تطبيق. اكتب تفسيرك، مو بس الحرف.

**رموز الحالة:** `[ ]` لم يُجب بعد، `[x]` أُجيب وصُحح، `↻` يحتاج مراجعة. هذه أسئلة جديدة للاستذكار؛ لا يعني وجودها أنك حليتها سابقاً.

## المجموعة A — PHP أساسيات

**Q01 [ ] — مفهوم:** شنو الفرق بين Variable وFunction؟ أعطِ مثالاً صغيراً من نظام الطلاب.

**Q02 [ ] — تتبع كود:** شنو الناتج وليش؟

```php
$a = 5;
$b = '5';
var_dump($a == $b);
var_dump($a === $b);
```

**Q03 [ ] — سيناريو:** عندك Form باسم `name`، المستخدم ضغط إرسال وخلّى الاسم فارغاً. شنو تسلسل الخطوات الآمن على السيرفر قبل INSERT؟

**Q04 [ ] — تتبع كود:**

```php
$names = ['Ali', 'Sara'];
foreach ($names as $name) {
    echo strtoupper($name) . ' ';
}
```

توقع النتيجة.

**Q05 [ ] — فهم:** ليش `empty('0')` تحتاج انتباه إذا كانت القيمة الصفرية مقبولة في النظام؟

**Q06 [ ] — تطبيق:** اكتب Function اسمها `isAdult(int $age): bool` ترجع نتيجة مناسبة لعمر 18 فما فوق (تمرين مستقل، لا تحتاج كود Laravel).

## المجموعة B — MySQL / PDO

**Q07 [ ] — مفهوم:** ما المقصود بـ Primary Key وForeign Key؟ طبّق التعريف على `students.id` و`students.user_id`.

**Q08 [ ] — تتبع SQL:** شنو خطورة تنفيذ الأمر التالي من دون `WHERE`؟

```sql
UPDATE students SET stage = 'Fourth';
```

**Q09 [ ] — أمان:** ليش نستخدم `PDO::prepare()` و`execute()` بدلاً من دمج إدخال المستخدم مباشرة في SQL؟

**Q10 [ ] — مقارنة:** ما الفرق بين `fetch()` و`fetchAll()`؟

**Q11 [ ] — سيناريو:** نريد كل Email فريد. هل Validation وحدها كافية لمنع أي تكرار متزامن؟ شنو القيد المطلوب في DB؟

**Q12 [ ] — تحليل كود:**

```php
$stmt = $pdo->prepare('SELECT * FROM users WHERE id = :id');
$stmt->execute(['id' => 7]);
$user = $stmt->fetch(PDO::FETCH_ASSOC);
```

شنو شكل `$user` المتوقع إذا السجل موجود؟ وإذا غير موجود؟

## المجموعة C — Laravel MVC وCRUD

**Q13 [ ] — مفهوم:** عندنا `GET /students/3/edit` و`PUT /students/3`. أيهما يستدعي `edit()` وأيهما `update()`؟

**Q14 [ ] — تتبع:** شنو الفرق بين `return view(...)` و`return redirect()->route(...)` بعد حفظ طالب؟

**Q15 [ ] — سيناريو:** ليش `@csrf` لازم في Form إرسال على الويب؟

**Q16 [ ] — مقارنة:** شنو الفرق بين `Student::find(99)` و`Student::findOrFail(99)` إذا ID ما موجود؟

**Q17 [ ] — تحليل Validation:** عند التحديث تريد تسمح للطالب يحتفظ ببريده نفسه؛ ليش نستخدم `unique:students,email,` مع ID الطالب الحالي؟

**Q18 [ ] — تطبيق:** عندك Form تحديث HTML. كيف توجه الطلب إلى `students.update` مستخدماً `@csrf` و`@method('PUT')`؟ اكتب الفكرة بدون نسخ.

**Q19 [ ] — أمان:** إذا `Student::create($request->all())` استقبل `user_id` من المتصفح، شنو الخطر عندما `user_id` ضمن `$fillable`؟

**Q20 [ ] — سيناريو:** نريد إظهار خمسة طلاب في كل صفحة. ما الدالة المستخدمة، وأين نعرض روابط الصفحات؟

## المجموعة D — علاقات Eloquent والصور

**Q21 [ ] — علاقة:** طالبة لديها بطاقة واحدة وثلاث كتب. ما علاقات `Student` المناسبة لكليهما؟

**Q22 [ ] — علاقة:** طالب يدرس في عدة دورات، والدورة تضم طلاباً متعدّدين. ما نوع العلاقة وما فائدة Pivot Table؟

**Q23 [ ] — تتبع:** ماذا تفعل `courses()->sync([])`؟ هل تحذف جداول Course نفسها؟

**Q24 [ ] — أداء:** اشرح مشكلة N+1 عندما نعرض اسم المستخدم الذي أضاف كل طالب، ثم اكتب فكرة الحل بـ `with()`.

**Q25 [ ] — ملفات:** بعد تنفيذ `$student->delete()`، هل صورة الطالب تُحذف تلقائياً من `storage/app/public`؟ وضّح.

**Q26 [ ] — مقارنة:** الفرق بين `with('books')` على Query و`$student->load('books')` على Model موجود؟

## المجموعة E — Policies وGate و403

**Q27 [ ] — تتبع:** إذا `$student->user_id = 1`, و`$user->id = 2`, و`update()` في Policy ترجع نتيجة `===`، شنو قيمة `Gate::forUser($user)->allows('update', $student)`؟

**Q28 [ ] — مقارنة:** `allows()` رجعت `false`. هل هذا يعني أن HTTP 403 انرسل فوراً؟ متى يظهر 403 عادةً؟

**Q29 [ ] — أمان:** إخفاء زر Delete بـ `@can('delete', $student)` وحده يكفي لمنع الحذف؟ ليش؟

**Q30 [ ] — تحليل:** لو `update` ترجع `true` و`delete` ترجع `false` في Policy، هل المستخدم يكدر يحذف؟ شنو الـ Ability التي تُفحص؟

**Q31 [ ] — سيناريو:** يوجد طالب يملكه المستخدم 1، وشخص آخر يريد فتح `/students/5/edit`. شنو نقطتا الحماية المطلوبتان: إظهار رابط التعديل أم حماية الـ Controller؟

**Q32 [ ] — ترتيب:** هل يصح كتابة `$student->save()` قبل `authorize('update', $student)`؟ اشرح السبب.

## المجموعة F — مراجعة الدرس الحالي Policy::before()

**هذه هي مجموعة الستة أسئلة المناسبة لنقطة الاستئناف الحالية. لا تعتبرها محسومة قبل إجابتك.**

**Q33 [ ] — مفهوم:** فسّر الفرق بين `return true`, `return false`, `return null` داخل `StudentPolicy::before()` بكلماتك.

**Q34 [ ] — تتبع كود:**

```php
public function before(User $user, string $ability): ?bool
{
    if ($user->is_admin) {
        return true;
    }

    if ($user->is_blocked) {
        return false;
    }

    return null;
}
```

افترض مستخدماً `is_admin=true` و`is_blocked=true`. شنو يصير؟ وهل يصل للشرط الثاني؟

**Q35 [ ] — تغيير المتطلبات:** إذا قررنا أن الحظر يجب أن يسبق أي صلاحية مسؤول، شنو التعديل المنطقي الواجب على ترتيب الشرطين؟

**Q36 [ ] — سيناريو:** مستخدم ليس Admin وليس Blocked، لكنه يملك الطالب المطلوب. `before()` رجعت `null`، و`update()` تقارن الملكية. شنو القرار النهائي؟ وليش؟

**Q37 [ ] — تمييز:** ما الفرق في النطاق بين `Gate::before()` العامة و`StudentPolicy::before()` داخل سياسة واحدة؟

**Q38 [ ] — حالة حدية:** عند Policy فيها `before()` لكن ما بيها Method اسمها `export`. هل مجرد وجود `before()` يضمن تنفيذها لـ Ability اسمها `export`؟ ناقش الشرط الخاص بـ Laravel.
